# Bugfix Requirements Document

## Introduction

Six tests in the CI suite fail on Windows (Python 3.13, win32) because the test code makes POSIX-specific assumptions about path behavior. The `resolve_xdg_path()` implementation correctly uses `pathlib.Path` which creates the host-native path type on each platform — the bug is in the tests, not the implementation. Three distinct failure categories exist: (1) POSIX-style paths without drive letters are not considered absolute by `WindowsPath.is_absolute()`, (2) `write_text()` without explicit encoding uses the system locale (cp1252 on Windows) which cannot encode certain characters generated by Hypothesis, and (3) error message assertions use forward-slash path literals that don't match Windows backslash representations.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN `test_all_paths_are_absolute` runs on Windows with POSIX-style environment values like `HOME=/home/testuser` THEN the system fails because `WindowsPath("/home/testuser/.cache/debcraft/mirror").is_absolute()` returns False (no drive letter)

1.2 WHEN `test_result_is_absolute_path` property test runs on Windows with POSIX-style paths in environ THEN the system fails because `WindowsPath` requires a drive letter (e.g., `C:\`) to consider a path absolute

1.3 WHEN `test_tmp_files_removed_and_others_untouched` runs on Windows and Hypothesis generates filenames containing characters like `\x80` THEN the system crashes with `UnicodeEncodeError: 'charmap' codec can't encode character '\x80'` because `write_text()` defaults to the system locale encoding (cp1252) on Windows

1.4 WHEN `test_error_message_identifies_unwritable_path` runs on Windows THEN the system fails because the test matches against `/fake/config` but the error message contains `\fake\config` (Windows path separators)

### Expected Behavior (Correct)

2.1 WHEN `test_all_paths_are_absolute` runs on Windows THEN the system SHALL use platform-appropriate absolute paths in test environment values (e.g., `C:\Users\testuser` style paths when running on Windows, or use `PurePosixPath` for validation) so that the assertion passes

2.2 WHEN `test_result_is_absolute_path` property test runs on Windows THEN the system SHALL provide environment values that produce paths recognized as absolute by the host platform's path implementation

2.3 WHEN `test_tmp_files_removed_and_others_untouched` runs on Windows THEN the system SHALL explicitly specify `encoding="utf-8"` in `write_text()` calls so that Hypothesis-generated filenames with non-ASCII content bytes can be written regardless of system locale

2.4 WHEN `test_error_message_identifies_unwritable_path` runs on Windows THEN the system SHALL use a platform-agnostic pattern (e.g., `re.escape(str(Path("/fake/config")))` or match on `fake` and `config` path parts) so that the regex matches regardless of path separator

### Unchanged Behavior (Regression Prevention)

3.1 WHEN any of the 6 affected tests run on Linux THEN the system SHALL CONTINUE TO pass with the same assertions and behavior as before

3.2 WHEN any of the 6 affected tests run on macOS THEN the system SHALL CONTINUE TO pass with the same assertions and behavior as before

3.3 WHEN other tests in the same test files (non-`is_absolute` assertions, non-error-message-matching assertions) run on any platform THEN the system SHALL CONTINUE TO pass unchanged

3.4 WHEN the `resolve_xdg_path()` implementation is called at runtime THEN the system SHALL CONTINUE TO produce platform-native absolute paths without any changes to the implementation code
